## 项目架构阅读

完成了对 StreackLib 0.6.0 项目全部核心源文件的系统性阅读，理解了五层架构设计：

1. **入口层**：`forBukkit`（JavaPlugin 入口）→ `StreackLib`（ENV/manager 核心）
2. **后端抽象层**：`StreackLibDefaultBackend`（抽象后端）← `StreackLibBukkitBackend`（Bukkit 实现，继承）
3. **功能模块层**：HTTPServer、SConfig、SMail、SDatabase
4. **工具与基础设施**：SEventCentral、SFile、MCColor、nbtHandler
5. **基础类型与日志**：logger、updateChecker、StreackLibNewable

### 关键发现
- SDatabase 模块为 0.6.0 新增，连接池（SdbManager）和执行逻辑（SdbActionContext.execute()）尚未实现
- SConfig 是最大的源文件（66.4KB），支持 JSON/YAML/TOML/INI/NBT/SNBT/Properties 等 7+ 种格式
- 跨平台后端架构通过 volatile `backend` 字段实现，manager 持有后端引用
- SEventCentral 仿 JavaScript Event 模型，支持强/弱引用监听器
- HTTPServer 基于自定义 NanoHTTPd fork，支持 IP 封禁同步游戏内封禁
- SMail 支持 SMTP 和 DKIM 自签名直投（SELFSIGN）两种模式
- StreackLibNewable 为 0.6.0 新增的公共基类，提供 INSTANCE_ID 和 TIME_STAMP

## SDatabase 模块后端实现

按照架构文档完成了 SDatabase 模块的完整后端实现（commit `f547b73`）：

### 新增文件
- **Backend.java**：包私有接口，定义 `borrowConnection()` / `close()` 契约
- **SqliteBackend.java**：SQLite 单连接后端，`synchronized` 借出，Proxy 拦截 `close()` 实现共享连接
- **MysqlBackend.java**：MySQL HikariCP 连接池后端，配置 10 最大连接 / 2 最小空闲
- **SdbAction.java**（重写）：AutoCloseable 事务手柄，`apply(ctx/rawSql)` 执行 SQL，`commit/rollback/close` 控制事务
  - `close()` 未提交时自动回滚 → `setAutoCommit(true)` → `connection.close()` → `manager.release()`
  - 新增 `readResultSet()` 将 ResultSet 转为 `List<SConfig>`

### 重写文件
- **SdbManager.java**：全局静态连接池管理，`POOLS` + `REFS` 双 ConcurrentHashMap，`POOL_LOCK` 原子保护
  - `acquire(profileConf, profileId)`：computeIfAbsent 创建 + merge 引用计数
  - `release(profileId)`：递减引用计数，≤0 时 remove + close
  - `createBackend()`：根据 mode 字段工厂创建 SqliteBackend 或 MysqlBackend
- **SdbDatabase.java**：移除 inner Backend 接口，重写 act() API
  - `act()` → 返回 `SdbAction`（事务手柄）
  - `act(ACTION_TYPE, Consumer)` → 语法糖一键执行（auto-commit）
  - `act(String)` → 直接执行原始 SQL
  - 新增 `profileId` / `SdbManager` 字段

### 修改文件
- **SdbActionContext.java**：删除 `execute()` 方法（职责移入 SdbAction.apply()），更新 Javadoc
